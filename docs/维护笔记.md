## 1. 这是什么

给 DSH 桌面版（实测 0.2.1-rc.5）做的右栏图片插件，五部分：

- **会话图片** —— 当前会话里的图（图片库里 `sessionId` 匹配的子集）+ 顶部「未归档区」
- **工作台** —— 自绘画布，圈选 / 标注 / 蒙版，用来表达改图意图
- **图片库** —— 磁盘上的图片资产管理（扫描 / 分组 / 来源筛选 / 时间筛选 / 搜索 / 收藏 / 删除）
- **出图** —— 内建 `generate_image` 工具，任何会话都能调
- **出图日志** —— 每次出图的完整请求 / 轮询 / 响应记录（诊断用）

## 2. 装与更新

插件用 `link:` 装，**改完代码要 build + 重启**才生效。

```powershell
cd <插件目录>
npm install          # 首次
npm run build        # 改完源码必须
npx tsc --noEmit     # esbuild 不做类型检查，这步能提前抓错
```

接进 profile（`~/.dsh/profiles/desktop/package.json`）：

```jsonc
"dependencies": { "dsh-session-gallery": "link:<插件目录绝对路径>" },
"dsh": { "profile": { "bundles": [ ..., "dsh-session-gallery" ] } }
```

> 也可以直接 `dsh plugin --profile desktop add <插件目录>`，它会自己写这两处。

### 哪一半需要重启

| 产物 | 改了要重启吗 |
|---|---|
| `lib/client.js`（界面、面板、设置页、大图） | **不用**，客户端插件是热加载的 |
| `lib/index.js`（路由、工具、curl 出图） | **必须完全退出 DSH 再启动** |

> 「客户端插件不会热更新」是错的，2026-11-02 实测纠正。反过来更危险：
> **宿主半侧改完没重启，跑的还是旧代码**，会把「已修好」误判成「还是坏的」。
> 判断构建有没有真的加载：看 sidecar / 出图日志里新字段有没有出现。

### 客户端约定

- tab 注册：`sidebarRightTabs.register({ id, kind, priority, title, guide })`，正文用 `slots.register`，key 必须逐字相同
- client bundle 是自注册懒式 CJS（`window.__ModuleLoader__.load`），`react` / `react/jsx-runtime` 必须 external
- **不要加 `@deepseek-ai/dsh-*` 的 peerDependencies**（0.2.x 会静默跳过插件）
- 样式统一前缀 `dshsg-`，用 `--dsw-*` 变量
- 面板外面套了 `PanelErrorBoundary`，崩溃时显示错误而不是白屏

## 4. 数据模型 · 不能改的部分

```
图片库（唯一存储，磁盘）
├─ 脚本产出\<哈希12>.png + .json                      ← generate_image 直出
├─ 会话导入\<会话短id>\<时间>-<哈希12>.png + .json   ← 未归档区「存入」落这里
├─ 手动导入\<时间>-<哈希12>.png + .json
├─ .workbench\                                        ← 工作台导出（扫描跳过）
└─ .dshsg-trash\                                      ← 删除的图（扫描跳过）

会话图片 = 图片库中 sidecar.sessionId === 当前会话 的图（严格子集）
未归档区 = 会话事件里的图片 − 已归档（按 sourceAttachmentId 匹配）− 忽略列表
```

### 一张图只有两个合法状态

| 状态 | 含义 | 出现在哪 |
|---|---|---|
| **未归档** | 对话里出现过，但还没进图片库 | 只在「会话图片」顶部的未归档区 |
| **已归档** | 库里有一份 `sidecar.sessionId === 本会话` 的图 | 「会话图片」归档区 **且** 「图片库」 |

判据就两条，**别加补丁**：

```ts
merged     = sessionFiles                                   // 只看 sessionId 匹配
unarchived = images.filter(i => !archivedIds.has(i.id) ...)  // 只看 sourceAttachmentId
```

> **2026-10-30 血泪教训**：为了让「脚本直接写库的图」也出现在归档区，先后加过
> 「全库 hash 匹配」「会话事件匹配」，结果图在「归档区/未归档区/哪都不在」之间来回跳，
> **返工一整天**。数据不对就修数据，不要改判据。

### sidecar 字段（v2，2026-11-05 起）

```json
{
  "schemaVersion": 2,
  "no": "G-007",
  "origin": "user | tool | script | manual | site | folder",
  "sessionId": "session-…",
  "sourceAttachmentId": "sha256:…",
  "prompt": "…", "model": "gpt-image-2", "channel": "plugin",
  "size": "9:16", "resolution": "1k", "quality": "high",
  "referenceCount": 1, "taskId": "task_…",
  "width": 941, "height": 1672, "bytes": 3009263,
  "hash": "30b4ff9c7f6d", "costUsd": 0.0085,
  "createdAt": "…", "importedAt": "…",

  "groups": [], "labels": [], "title": "", "updatedAt": "…"
}
```

- `sessionId` 是「会话图片」栏**唯一的认领依据**
- `size` 只在用户明确指定时才写（不传时上游自己挑比例，写死会记假值）
- `costUsd` 记**这张图自己那次任务**的花费，不是本批总额
- `createdAt` 是**排序和时间筛选的唯一依据**（没有它才退回文件修改时间）

### 与外部素材库共用同一份 json（可选，默认关）

「素材库」是一套可选的约定：图片库目录可以由另一个程序（例如自建的素材库网站）
一起读写，两个前端各自只写自己那半字段。

- **开关**：设置页「与 AI 参考库站点共用这个目录」→ 打开后才发 `G-` 编号
- 关着的时候行为与不带这个功能时完全一样（不发号、不扫库）

不能违反的几条：

1. **写 sidecar 一律走 `writeSidecarMerged()`**，它会 `{ ...旧内容, ...本次字段 }` 合并。
   **绝不能整文件覆盖**——对方会在同一份 json 里写 `no` / `groups` / `labels` / `title`，
   覆盖会把这些一次性抹掉，而且两边都不报错，属于最难查的丢数据。
2. **现有三处写入点**：出图（`generateImagesInner`）、手动导入、归档。新增写入点也必须走合并写。
3. **编号**：插件发 `G-`（落盘时扫库取最大号 +1，`maxGalleryNo` / `makeNoAllocator`），
   对方发 `U-`。**旧号一律沿用**（同一张图重复出图不换号）。
4. **发号器不缓存**：对方是另一个进程（甚至另一台电脑经同步写入）也会发号，缓存随时过期。
5. `origin` 六档：`script` / `manual` / `user` / `tool` / `site` / `folder`。
   后两个插件只显示不写。图片库的来源筛选里还留着 `assistant` 一档，那是历史遗留，
   现在没有任何代码会写这个值。
6. 清理逻辑（`.workbench`、gen 暂存）**不要扩到根目录里的图片**。

### 设计上定死的规则

1. **图片库是唯一存储**：会话图片只是筛选视图
2. **会话图一律手动归档**：没有自动归档（2026-11-01 删掉了整条轮询链路）
3. **中间产物不进库**：没进会话的截图 / 读图不进任何视图
4. **小缩略图上不放危险按钮**：忽略只能在大图里
5. **参数与提示词直接显示，可一键复制**
6. **设置页在侧栏内联**，不要居中浮窗
7. **删除默认走回收站**，永久删除要勾选
8. 三个 tab 顺序：**会话图片 / 工作台 / 图片库**
9. **未归档是易失的**：只来自对话事件窗口，会话变长会滑出。**不是 bug，不要修**
10. **出图配置不进仓库**（在 `~/.dsh/cache/`，Key 在 `.credentials.yaml`）

## 5. 出图

插件启动时注册 `generate_image` 工具，AI 的工具列表里天然有它，**任何会话都能用**。

### 工具参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `prompt` | string | 必填 |
| `model` | string | 可选。传了就用传的，没传用设置里的默认模型 |
| `size` | string | 可选。比例。**不传时上游自己挑**（实测 1:1 的请求回了 1536×1024） |
| `resolution` | string | 可选。`1k` / `1.5k` / `2k` / `4k` |
| `quality` | string | 可选。`low` / `medium` / `high` / `xhigh` / `max`，**只有 gpt-image-2.5 认** |
| `n` | number | 可选 1–6。**插件内部并发提交**，不传给上游；总耗时≈一张 |
| `images` | string[] | 可选。参考图本地绝对路径，最多 10 张，png/jpg/webp/gif，单张 ≤20MB |
| `mask` | string | 可选。局部重绘蒙版（本地 png，透明处=允许重绘）。见下 |
| `extra` | object | 可选。模型专有参数原样透传（`background` / `layer_decomposition`…） |

**没有白名单、不按模型分表。** 插件当通道不当守门人：参数原样传，让上游用自己的
文档校验，错误原话透回。「哪个模型支持什么」归调用方 / 文档管。

### 中转站协议（2026-11-02 实测）

**提交** `POST /v1/images/generations`：

```json
{"code":200,"data":[{"status":"submitted","task_id":"task_01M6…"}]}
```

`task_id` 在 **`data[0]`** 里，**不在顶层**。同步站（OpenAI 兼容）则直出 `{"data":[{"url":"…"}]}`。

**轮询** `GET /v1/tasks/{id}`（20–45 秒）：

```json
{"code":200,"data":{"status":"completed","progress":100,"cost":0.0085,
  "result":{"images":[{"url":["https://…png"],"expires_at":1793711160}]}}}
```

**`url` 是数组，不是字符串。** 结果 URL 24 小时过期，拿到立刻下载落盘。

- `cost` 单位美元
- 失败时读 `error.message`（顶层或 `data.error.message`）——**必须原样透传**，
  且**只报事实，不推断「重试有没有用」**（见 §8.3）

### 垫图

走 `image_urls`，数组元素可以是公网 URL 或 `data:image/png;base64,…`，可混用，
最多 15 张 / 单张 ≤20MB / 总共 ≤256MB。**插件用 base64，不需要上传接口**。

### mask 局部重绘（2026-11-06 实测通过）

`generate_image` 的 `mask` 参数（本地 png 绝对路径）。插件读文件 → base64 → 请求体
`mask_url`（**实测 data URI 可用**，不用先上传公网）。

- **只支持** `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` / `gpt-image-2-official`；
  普通 `gpt-image-2` **不支持**（会明确报错，不静默忽略）
- **提交前校验**（全部免费，6 项实测逐字通过）：协议必须异步型 → 模型支持 →
  必须同时传 `images` → 文件存在 → **<4MB** → PNG → **有 alpha** → 与**第一张参考图**同尺寸
- **语义**：透明区域 = 允许重绘；**mask 外不保证不变**（文档明说，实测原主体也有细微变化）
- **成本**：2.5 / 1k / low / 单张 1254×1254 输入 = **$0.0146**
  （纯文生 low 才 $0.0048，差约 3 倍——输入图按 input token 计费）
- **记录**：sidecar 写 `mask: {name, bytes, width, height}`；出图日志写 `request.mask`
- **工作台配合**：2026-11-06 起「生成改图请求」**只导蒙版图**（标注图已去掉），
  文本里给 `蒙版图：<路径>（透明处 = 允许重绘；传给 generate_image 的 mask 参数）`；
  插件**不会自动发送、也不会自动注入 mask**，执行方要自己把路径传给 `mask`

### 各模型参数**不一样**（重要）

| | `gpt-image-2` | `Seedream-5.0-Pro` |
|---|---|---|
| `resolution` | 1k / 2k / 4k | 1k / 1.5k / 2k（**4k 直接 400**） |
| `size` 比例 | 15 种（含 5:4、4:5、3:1、1:3、9:21） | 10 种（`9:21` 会 400，不静默回退） |
| 参考图上限 | 15 张 | 10 张 |
| 专有参数 | `official_fallback` | `background`、`layer_decomposition`、`output_format` |
| `n > 1` | 静默忽略**但照扣钱** | 直接 400，不扣钱 |

### quality 实测（2.5 按档位计费）

`gpt-image-2.5-sunburst`，同 prompt / 1:1 / 1k：

| quality | cost | 用时 |
|---|---|---|
| `low` | **$0.004768** | 9 秒 |
| `high` | **$0.042208** | 33 秒 |

**差 8.85 倍。** 边界行为：

- `gpt-image-2` + `quality` → 静默忽略，不影响计费
- `2.5` + 非法 quality（如 `nonsense`）→ **不报错，静默回退 `low`**
- `gpt-image-2` + `resolution: "1.5k"` → **400**，且说清「只支持 1k/2k/4k」

> **不传 quality 时默认 `auto`，而 `auto` 会按 `max` 档预扣资金**（结算按实际用量）。
> 给 2.5 出图务必显式指定档位，否则余额会被占一大笔。

### 配置与诊断

- 配置在 `~/.dsh/cache/session-gallery/gen-config.json`（地址 / 协议 / 代理 / 默认模型）
- Key 在 `~/.dsh/.credentials.yaml`，键名由设置里的「凭据名」决定
- 诊断三处：`boot-diag.log`（启动链路 + curl 探测 + 前端崩溃）、`gen-diag`（工具注册状态）、`gen-config`（当前配置）
- **桌面版宿主 stdout 不落盘**，`console.log` 全进虚空 —— 排查一律靠上面三处

## 6. 出图日志（2026-11-03）

中转站后台的任务日志有保留上限、会滚掉；要事后分析「某类图为什么失败」（尤其审核拦截），
必须自己留完整链路。

- **存储**：`~/.dsh/cache/session-gallery/gen-tasks/YYYYMMDD.jsonl`，按天追加
  - **固定目录，不跟图片库走**（日志是运行记录，不是图片资产）
  - 不设上限、不写图片二进制、不写密钥；写日志失败绝不影响出图
- **每条记录**：`id / startedAt / elapsedMs / status / source / machine / sessionId /
  request（含 prompt 全文、参考图名字+大小）/ children[]（每个子任务的 taskId、
  提交响应原文、失败前的最后一轮轮询原文、轮询轨迹、cost、urls、error）/ result / error`
- `source`：`live`（实时）/ `sidecar` / `apimart`（历史补录）
- **界面**：图片库工具栏「出图日志」→ 列表 + 仅失败筛选 + 搜索 + 详情 + 复制 JSON + 清空
- **补录脚本**：`import-sidecar-logs.mjs`（从 sidecar 反推成功记录）。
  另有两个一次性脚本（按 task_id 补失败记录、从会话日志回填老图 prompt）没随仓库发布，
  需要时从开发历史里找。

### 能力边界

| 想要 | 能不能 |
|---|---|
| 按 task_id 查详情（`error.message` / cost / 耗时） | ✅ 有 API key 就行 |
| 列出全部任务 | ❌ 要网页登录态 |
| 查提示词 | ❌ API 不返回，只能网页看 |

## 8. 踩过的坑

### 8.1 宿主插件 API（任何插件都会踩）

| 坑 | 现象 | 处理 |
|---|---|---|
| **服务方法被摘下来调用，`this` 丢失** | 工具始终注册不上；`hasRegister: true` 但抛 `Cannot read properties of undefined (reading 'layers')` | 必须带着对象调：`tools.register(def)`，不能 `const r = tools.register; r(def)` |
| **`apply()` 里直接读 `ctx.tools` 拿不到** | 静默失败，只打一行看不见的 warn | 用 `ctx.inject(['tools'], cb)` + `owner.get('tools')` 等就绪。别用模块级 inject（会让整个插件不加载） |
| **cordis 的 `ctx` 是 Proxy** | 读未声明的服务属性会**抛错**而非返回 undefined | 裸读包 `try/catch`，优先 `owner.get(name)` |
| **桌面版 stdout 不落盘** | `console.log` / `console.warn` 全进虚空 | 自己写 `boot-diag.log` 或开诊断路由 |
| **定时器没清理** | DSH 关不掉、更新装不上（`graceful task teardown`） | 任何 `setInterval`/`setTimeout` 都要接 `ctx.effect` 返回 disposer，或 `unref()` |

### 8.2 前端

| 坑 | 现象 | 处理 |
|---|---|---|
| **`e.currentTarget` 在 setState 函数式更新里读** | 设置页输入任何字符 → 整个右栏白屏 | 先 `const v = e.currentTarget.value` 再 setState |
| **面板没有错误边界** | 一处渲染抛错 → 整棵组件树卸载，连 tab 都没了 | `PanelErrorBoundary` + `/client-log` 上报 |
| **浏览器原生图片拖拽抢 pointer 事件** | 工作台画笔/框选全哑 | `onDragStart` preventDefault + `-webkit-user-drag: none` + pointerdown preventDefault |
| **lightbox 顶部条压住窗口按钮** | 右上角最小化/关闭浮在页面上层 | 用 `windowControlsOverlay.getTitlebarAreaRect()` 实测，Electron 兜底 38px |
| **工具栏数字用「全局集合大小」而不是「当前视图匹配数」** | 收藏按钮显示「♥ 收藏 2」，点开一张都没有 | 收藏是**两个视图共用一份数据**，拿 `favorites.size` 当按钮数字必然多算。两个视图各自算 `列表.filter(isFavorite).length` |
| **React 的 `onWheel` 是 passive** | 对比视图里 `preventDefault` 无效，滚轮带着整个页面滚 | 用原生 `addEventListener('wheel', h, { passive: false })` |

### 8.3 出图链路

| 坑 | 现象 | 处理 |
|---|---|---|
| **请求体走命令行会被长度限制截断** | 垫图（base64，3 MB+）必失败 | Windows 命令行上限约 32767 **字符**。body 超 8000 字符就写临时文件用 `--data-binary @文件` |
| **下载失败静默丢图** | `n=2` 出 2 张、扣 2 份钱，只入库 1 张，还报「已生成 1 张」 | 下载失败重试一次，仍失败就记进 `failures` 并在返回里明说原因 |
| **`failed` 被误报成「超时」** | 上游真实原因被吞掉 → 上层误判成拥堵，**擅自换模型出图** | failed 时必须读 `error.message` 原样透传 |
| **给失败信息加「操作建议」** | 写过「这是站点明确拒绝，原样重试没用，改写措辞后再试」，结果**原样重试一次就成功了** | 插件只报**可观测事实**（状态、原文、任务号），**不推断因果、不预测重试结果、不替调用方决定下一步** |
| **`costUsd` 记本批总额** | n 张图各写一遍总额，像花了 n 倍钱 | 按任务配对，每张记自己那次的花费 |
| **`task_id` 在 `data[0]` 不在顶层** | 取不到 → 当成同步接口 → 报「没有拿到图片地址」 | 兼容两者；`url` 也是**数组**不是字符串 |
| **`curl.exe` / `explorer.exe` 靠 PATH** | 检测报「连不上」但命令行正常；「打开文件夹」提示成功却没窗口 | 用 `resolveCurl()` / `resolveExplorer()` 按 `%SystemRoot%\System32` 拼绝对路径 |
| **Node 的 `fetch` 不读系统代理** | 中转站请求超时 | 全部走 `curl.exe -x <代理>` |
| **改了宿主代码只 build 没重启就测** | 测试全跑在旧构建上：`mask` 参数被静默忽略，6 次「应当报错」的用例**全部成功出图**，白花 $0.0831 | 测新宿主逻辑前**必须先重启 DSH**；用「sidecar/日志里新字段是否出现」确认构建已加载 |

### 8.4 DSH 环境（跟插件无关，但会复发）

| 坑 | 现象 | 处理 |
|---|---|---|
| **「禁用第三方插件」按钮** | 界面回英文、主题字号丢失、所有插件消失 | 它清空 `cordis.patch.yml`（DSH 用默认值重建）并把 `bundles` 从 9 项砍到 2 项。恢复靠同目录的 `package.json.bak-*` / `cordis.patch.yml.bak-*`。要临时排除插件，用 `- { id, disabled: true }` 补丁 |
| **起不来 + `Web authentication failed`** | 弹「could not start」，禁用插件也无效 | Electron 的 Cookie SQLite 库损坏。删 `%APPDATA%\@deepseek-ai\dsh-desktop\Network\Cookies*` 后重启。**判断是不是插件害的：点过「禁用第三方插件」还起不来，就不是** |
| **多实例并存 / 频繁重启** | teardown 报错、bad port、Cookie 更容易坏 | 托盘退出后确认任务管理器无残留再启动 |
